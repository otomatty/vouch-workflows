# Vouch

この文書は Vouch を配ったプロジェクトの開発に適用する。判断はモデル、機械的な検査・記録はフックが担う。状態機械は作らず、成果物を状態、監査ログを証跡とする。
現在の配布は doctor、読み取り専用 status、Intent の下書き作成、人の明示入力による確認点と承認の記録・適用に対応する。Build 以降の Skill 操作と引用の検査フックは未実装である。監査ログ・フック設定・承認済み成果物へのツールからの書き込みと、承認済み計画のない実装のファイル編集は、登録したツールに限りフックが遮る。文書の規則が機械的に強制済みとはみなさない。

## ステージと参照元

正典は `{{HARNESS_DIR}}/registry/workflow.json` と `{{HARNESS_DIR}}/registry/project-documents.json`。

| ステージ | 成果物と目的 |
| --- | --- |
| Intent <!-- stage:intent --> | intent.md に受入基準・非ゴール・最小実装・分割・リスク・検証方法を置き、人が採択する |
| Design <!-- stage:design --> | design.md に契約と差分図を置く。高リスクまたは計画が要求した時に行う |
| Build <!-- stage:build --> | 契約→テスト→実装のコミットと build-log.md の検証記録を残す |
| Verify <!-- stage:verify --> | 別コンテキストで検証し、review.md を Review Brief として人が PR を判断する |

主張には証拠、成果物には参照元、判断依頼には選択肢のメリット・デメリット・根拠・推奨案を添える。識別子とイベント名は英語の正典を使う。[R-PROJECT-2]
専門知識は必要な時に読み、参照先の鮮度を確認する。根本原因を解決する最小の変更とし、理想形との差分を残す。根拠は決定記録 §4・§13。

## 不変条件と禁止事項 [R-PROJECT-4]

- 人の承認なしに approved にすること、承認を代行すること、承認済み計画なしに実装することは禁止する。PR はリスク階層にかかわらず人が Brief を読んでマージし、自動マージしない。[R-PROJECT-1]
- 証拠の捏造、証拠・参照元のない主張、根拠のない選択肢で人に判断を迫ることは禁止する。参照先の存在と受入基準から検証記録への対応を確認する。[R-PROJECT-2]
- 監査ログの手書き・編集は禁止する。モデルも人も追記せず、イベントの記録はフックを通す。status は読むだけで状態や承認を変更しない。[R-PROJECT-3]
- 本番データに触ること、main へ直接 push すること、根拠なく禁止事項を追加することは禁止する。[R-PROJECT-4]
- 合格を装うためのテストの改変・削除は禁止する。契約と失敗するテストを実装より先にコミットし、作成者とは別コンテキストで検証する。[R-PROJECT-5]
- 未回答の判断依頼は実行可能な既定案で進め、Brief §7 に残す。既定案を作れない時だけ判断を求める。既定適用を人の回答・承認に置き換えない。[R-PROJECT-6]
- 利用者側の実行時依存は Node と Git とする。Node が利用できない時の縮退モードは禁止する。doctor の案内で不足を伝える。[R-PROJECT-7]

規則の根拠と強制手段は `{{HARNESS_DIR}}/registry/enforcement-map.json` にある。pending の検査を実施済みと報告しない。

## プロジェクトの規約

採用済みの `vouch/rules.md` に DoD・依存ルール・確認点の粒度・Corrections を置く。未作成なら [日本語テンプレート]({{HARNESS_DIR}}/templates/ja/rules.md) または [English template]({{HARNESS_DIR}}/templates/en/rules.md) を基に、利用者の選択を反映する。既存の規約を上書きしない。
言語と確認点の選択肢・既定は workflow.json に従う。status と doctor は規約の作成、DoD の実行、変更の承認を行わない。
