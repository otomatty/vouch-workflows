Vouch 実装ルール — 構造・Lint・テスト

Vouch をこのリポジトリで実装するための、コードの構造、機械で強制できる実装ルール、厳格なテストのルール。判断でしか守れないルールは「reviewer」と明記し、それ以外はすべて Lint・型検査・テスト・CI 予算のどれかで落ちるようにする。ルールには ID を付け、違反時の出力に ID を出す。

01

方針

ルールは機械で守る。守れないルールは「判断」と明記する。この文書の各ルールは「強制手段」の列を持つ。手段は Biome / tsc / depcruise / markdownlint / knip / 構造テスト / CI 予算 / reviewer のいずれか。reviewer 以外は CI が落とす。reviewer は Vouch の reviewer エージェントと人の観点表に載せる。
実行時は依存ゼロ、開発時は使えるものを使う。利用者に配るフックは node の組み込みモジュールだけで動く plain JavaScript。このリポジトリの開発ツール（Biome、TypeScript の型検査、dependency-cruiser、markdownlint、knip、Stryker）は devDependencies に置き、配布物には含めない。
テストは契約を検証する。実装の写しを書かない。フックは子プロセスとして起動し、stdin / stdout / 終了コード / ファイルへの副作用だけを検証する。ライブラリは純粋関数として直接検証する。Skill と成果物テンプレートは構造テストで検証する。モデルの振る舞いは評価スイート（CI 外）で検証する。
Vouch の運用ルールは、このリポジトリ自身にも適用する。契約 → テスト → 実装のコミット順、主張には証拠、Review Brief で PR を出す。Vouch の最初の利用者はこのリポジトリ。
02

リポジトリ構造

v2 の core/tools/（10.5 万行の TS エンジン）は持たない。実行時コードは core/hooks/ だけで、他はすべて Markdown / JSON のデータ。依存の向きを固定し、dependency-cruiser で逆流を落とす。

03

ツールチェーン

用途ツール理由v2 から
実行時node ≥ 22（LTS）。package.json の engines で宣言決定記録 rev 3。組み込みの node:test、--experimental-test-coverage、t.plan() が使えるbun を廃止
パッケージ管理npm ＋ package-lock.json、CI は npm cinode に同梱。追加インストールなしbun.lock を廃止
Lint / 整形Biome 2.x（既存 2.4.16）。formatter.enabled: true に変更単一バイナリで JS / JSON を扱える。noRestrictedImports、useNodejsImportProtocol、noConsole、noProcessEnv が使える継続。整形も有効化
型検査TypeScript 6（既存）を tsc --checkJs --noEmit で使う。型は JSDocフックは plain JS のまま、型の厳密さは TS と同等にできる。ビルドが要らない.ts → .mjs ＋ JSDoc
依存方向dependency-cruiser（.dependency-cruiser.cjs）hooks ↔ hooks、lib → hooks、実行時 → npm、循環 を落とせる。Biome にはこの検査がない新規
Markdownmarkdownlint-cli2（.markdownlint-cli2.jsonc）Skill / テンプレート / AGENTS.md の見出し階層、コードフェンスの言語指定、行末空白を落とせる新規
未使用検出knip（既存 6）使われない lib、export、devDependency を落とす継続。entry を .mjs に
テストnode --test ＋ node:assert/strict。フレームワークなし依存ゼロ。カバレッジ閾値（--test-coverage-lines ほか）も組み込みbun test を廃止
ミューテーションStrykerJS（夜間のみ）「テストが本当に検証しているか」を lib に対して機械で測る。Vouch の破壊検査の自動版新規
JSON Schemaajv（テストの devDependency）レジストリと監査イベントの検証新規

npm scripts：lint（biome ＋ markdownlint ＋ depcruise ＋ knip）、typecheck（tsc --checkJs）、test（node --test、カバレッジ閾値つき）、package / package:check、check（lint ＋ typecheck ＋ test ＋ package:check ＝ CI と同じ）、mutate（Stryker、夜間）、eval（評価スイート、手動）。

04

実装ルール（Lint が効く）

「強制手段」が reviewer 以外のルールは、違反すると CI が落ちる。構造テストは tests/content/ と tests/registry/ の node --test で動くテストで、失敗メッセージにルール ID を含める。

STR — 構造

IDルール強制手段
STR-11フック1ファイル。ファイル名は vouch-<verb>-<object>.mjs（例 vouch-check-citation.mjs、vouch-record-event.mjs）。lib/ 以外のサブディレクトリを作らない構造テスト
STR-2依存の向き：hooks → lib のみ。lib → node: 組み込みと registry/*.json のみ。hooks 同士、lib → hooks、実行時 → tests、実行時 → npm、循環はすべて禁止dependency-cruiser
STR-3core/ にハーネス固有のパス（.claude/、.codex/、.agents/）を書かない。{{HARNESS_DIR}} トークンを使う構造テスト（grep）
STR-4dist/ は生成物。core/ と harness/ から package.mjs でバイト一致で再生成できるpackage.mjs --check
STR-5数値・一覧の正典は registry/*.json。Markdown や Skill に書かれた数（イベント数、ステージ数、予算）はレジストリと一致する構造テスト（v2 の t68 と同じ方式）
STR-6scripts/package.mjs はコピー・トークン置換・Markdown → TOML 変換だけを行う。条件分岐で内容を変えない（内容の差はすべて harness/<name>/ のファイルで表現する）構造テスト（package.mjs の import と行数）＋ reviewer

HOOK — フック

IDルール強制手段
HOOK-1依存ゼロ。import は node: 接頭辞つきの組み込みか ./lib/ だけ。package.json に dependencies を持たないBiome useNodejsImportProtocol ＋ dependency-cruiser ＋ 構造テスト（package.json）
HOOK-2決して例外で落ちない。エントリは run(main)（lib/io.mjs）だけで、main の例外は捕捉して stderr に ID つきで出し、終了コード 0 で抜ける。ハーネスを壊す終了コードは出さない契約テスト（不正な stdin で終了コード 0）＋ 構造テスト（エントリ形式）
HOOK-3終了コードの契約：0 ＝ 許可 / 何もしない、2 ＝ 遮断（理由は stderr、ハーネスがモデルに渡す）。それ以外は使わない契約テスト
HOOK-4stdout は JSON か空。人が読む文は stderr。console.* をフックと lib で直接呼ばない（lib/io.mjs の respond() / warn() だけ）Biome noConsole（lib/io.mjs のみ除外）
HOOK-5判断しない・外に出ない。node:http、node:https、node:net、node:dns、fetch、WebSocket を使わない。モデルや外部 API を呼ばないBiome noRestrictedImports ＋ noRestrictedGlobals（fetch, WebSocket）
HOOK-6ファイル I/O は lib/fs.mjs だけが node:fs を import する。監査ログは lib/audit.mjs の appendEvent() だけが開く（append-only、1行1イベント、書き込みは原子的）Biome noRestrictedImports（node:fs を lib/fs.mjs 以外で禁止）＋ 契約テスト
HOOK-7process.env は lib/env.mjs だけが読む。process.exit は lib/io.mjs だけが呼ぶBiome noProcessEnv（env.mjs のみ除外）＋ 構造テスト（process.exit の grep）
HOOK-8時刻と ID は lib/clock.mjs の now() / newId() だけ。Date.now()、new Date()、Math.random()、crypto.randomUUID() を他で呼ばない構造テスト（grep）
HOOK-9冪等。同じ入力で2回実行しても監査ログに同じイベントが2行入らない（イベント ID は入力とセッションから決定的に導出する）契約テスト（2回実行して行数を比較）
HOOK-10emit するイベント type は文字列リテラルで書き、registry/audit-events.json に存在する。動的に組み立てない構造テスト（appendEvent( の引数を静的に抽出して台帳と照合）
HOOK-11型は JSDoc で完全に付け、tsc --checkJs --strict --noEmit が通る。any と @ts-ignore を使わないtsc ＋ Biome noExplicitAny（JSDoc）＋ 構造テスト（@ts-ignore の grep）
HOOK-12行数予算：フック1本 ≤ 150 行、フック合計 ≤ 1,500 行、lib 合計 ≤ 3,000 行、lib 1ファイル ≤ 300 行（空行・コメント込み）CI 予算（registry/budgets.json）
HOOK-13時間予算：記録系フック p95 < 200 ms、検査系 p95 < 2 s（DoD 実行は rules.md のコマンドに従うため対象外）。予算は契約テストが計測する契約テスト
HOOK-14入力の検証：ハーネスのイベント JSON は lib/io.mjs のスキーマで検証し、未知のフィールドは無視、必須欠落は「何もしない」で抜ける。入力を信用してパスを組み立てない（パストラバーサル禁止：解決後のパスが project root 配下であることを検査）契約テスト（不正入力、../ を含むパス）

REG — レジストリ

IDルール強制手段
REG-1audit-events.json は JSON Schema（draft 2020-12）を持ち、各イベントに fields（必須 / 任意）、measures、pairs_with（開始 ↔ 完了）を定義する。台帳自体もスキーマで検証するregistry テスト（ajv）
REG-2台帳のすべてのイベントに、tests/fixtures/audit/<type>.jsonl の fixture と、それを emit する契約テストがある。台帳に載っているのに誰も emit しないイベントは削除するregistry テスト（台帳 × fixture × テストの突き合わせ）
REG-3audit-migration.json は v2 台帳の全 91 名をキーに持つ（v2 の audit-format.md を fixture として保存し、比較する）。値は Vouch 名か legacyregistry テスト
REG-4enforcement-map.json：Skill / AGENTS.md / テンプレートの中で MUST、NEVER、必ず、禁止 を含む行は [R-xxx] タグを持ち、map に hook | lint | test | reviewer | human のどれかで登録されている。登録のない強制語は落ちるcontent テスト
REG-5budgets.json が唯一の予算表。CI の予算検査はここだけを読むCI 予算

DOC — Skill・エージェント・テンプレート

IDルール強制手段
DOC-1SKILL.md の frontmatter はスキーマに従う（name、description、user-invocable、reads：常時読み込むか）。エージェントの frontmatter も同様（name、inputs、tools、disallowed）content テスト（ajv）
DOC-2行数予算：オーケストレータ ≤ 150 行、各ステージ Skill ≤ 200 行、AGENTS.md ≤ 60 行、エージェント ≤ 80 行。常時読み込み合計（AGENTS.md ＋ オーケストレータ ＋ rules テンプレート）≤ 8,000 トークン（推定：バイト数 ÷ 3 で保守的に見積もる）CI 予算
DOC-3Skill が指示するコマンドは許可リストから：node {{HARNESS_DIR}}/hooks/...、git ...、rules.md の DoD コマンド。bun、npx、curl を書かないcontent テスト（コードフェンス内の grep）
DOC-4ja / en テンプレートは同じ節 ID を同じ順序で持つ（<!-- sec:claims --> のようなマーカー）。片方だけの節を作らないcontent テスト
DOC-5Markdown の体裁：見出しは1段ずつ、コードフェンスに言語、行末空白なし、1行の長さは制限しない（日本語のため）markdownlint
DOC-6相対リンクと {{HARNESS_DIR}} を含むパスは、置換後に dist/ で実在するpackaging テスト
DOC-7テンプレートに必須の図（registry/diagrams.json）の Mermaid プレースホルダがあり、種類は安定5種のどれかcontent テスト
DOC-8Skill は「何を・いつ・完了条件」を書く。手順を逐一書かない。判断の指示には根拠（レジストリか決定記録の節）を添えるreviewer

DIST — 配布物

IDルール強制手段
DIST-1dist/ は package.mjs の出力とバイト一致package.mjs --check
DIST-2dist/ にテスト、fixture、golden、devDependency 由来のファイルを含まないpackaging テスト
DIST-3Claude の settings.json と Codex の hooks.json が登録するフックは実在し、登録されていないフックは存在しない（両方向）packaging テスト
DIST-4Codex の TOML エージェントは Markdown エージェントから生成し、往復（TOML → Markdown）で元に戻るpackaging テスト
DIST-5配布物を空のプロジェクトにコピーし、node .claude/hooks/vouch-doctor.mjs が exit 0 で通る（node と git 以外を要求しない）scenario テスト

DEP — 依存

IDルール強制手段
DEP-1package.json に dependencies がない。engines.node を宣言する構造テスト
DEP-2devDependencies は完全固定（^ / ~ なし）。package-lock.json をコミットし、CI は npm ci構造テスト（package.json の grep）
DEP-3使われない lib、export、devDependency を残さないknip
DEP-4CI は node 22 と 24 の両方で走るCI 設定
05

テストのルール

テストは node --test だけで動く。階層ごとに「何を・どう検証するか」を固定し、階層を横断するテスト（lib のテストがフックを子プロセスで起動する等）を書かない。

階層

階層対象検証の仕方必須の網羅CI
unithooks/lib/*.mjs直接 import。純粋関数として入力 → 出力。I/O は lib/fs.mjs をテスト用実装に差し替えるlib と 1:1 対応のテストファイル。分岐 95%毎 PR
hookshooks/vouch-*.mjs子プロセスで起動し、stdin / stdout / stderr / 終了コード / sandbox 内のファイルと events.jsonl を検証各フックに 5 ケース：許可、遮断、不正入力、冪等、時間予算毎 PR
registryregistry/*.jsonスキーマ検証、fixture との突き合わせ、v2 対応表の完全性全イベントに fixture ＋ emit するテスト毎 PR
contentskills / agents / templates / AGENTS.md構造テスト（frontmatter、予算、許可コマンド、強制語のタグ、ja/en 対応、必須図）全ファイル毎 PR
packagingscripts/package.mjs、harness/バイト一致、登録の両方向一致、TOML 往復、dist に不要物なし両ハーネス毎 PR
scenario1 Intent の一連の流れfixture のハーネスイベント列を順に投入し、最終的な intent フォルダと events.jsonl を golden と比較bugfix / feature / brownfield / 移行 の4本毎 PR
mutationhooks/lib/StrykerJS。生き残った変異はテストの穴ミューテーションスコア ≥ 80%夜間
evalSkill ＋ モデル代表タスクを Claude Code / Codex で実行し、監査ログから指標を集計。人の承認率も記録決定記録 §17 の指標手動 / リリース前

TEST — 書き方のルール

IDルール強制手段
TEST-1ランナーは node --test、アサーションは node:assert/strict のみ。ファイル名は *.test.mjs。配置は対象と鏡写し（core/hooks/lib/audit.mjs ↔ tests/unit/lib/audit.test.mjs）構造テスト（鏡写しの存在確認）＋ Biome noRestrictedImports（jest / vitest / bun:test）
TEST-2すべてのテストは t.plan(n) でアサーション数を宣言する。アサーションのないテスト、計画と実数が違うテストは失敗するnode:test の plan ＋ 構造テスト（test( ブロックに t.plan があるか）
TEST-3フックの契約テストはフックを import しない。helpers/runHook() で子プロセスとして起動する。lib のテストは子プロセスを起動しないdependency-cruiser（tests/hooks → core/hooks/*.mjs の import 禁止）＋ 構造テスト（tests/unit に child_process 禁止）
TEST-4隔離：各テストは helpers/sandbox() で mkdtemp の作業ディレクトリと git リポジトリを作り、そこにだけ書く。テスト間で状態を共有しない。--test-concurrency を CPU 数にしても通るCI が並列で実行 ＋ 構造テスト（process.chdir、リポジトリ直下への書き込み禁止）
TEST-5決定性：時刻と ID は helpers/fakeClock() で固定する。setTimeout による待機、Date.now()、Math.random() をテストに書かない。ネットワークは helpers/ が fetch を例外に差し替える構造テスト（grep）＋ helper
TEST-6golden：events.jsonl と描画済みテンプレートは tests/golden/ と全文比較する。更新は UPDATE_GOLDEN=1 でのみ行い、PR の Brief に差分の理由を書く。インラインスナップショットは使わないhelper ＋ reviewer（golden 差分の理由）
TEST-7fixture のハーネスイベント JSON は実機から記録し、harness と version を持つ。手で作ったイベントは synthetic: true を付ける。実機 fixture が1つもないイベント種別は契約テストで使えないregistry テスト（fixture のメタデータ）
TEST-8カバレッジ閾値：lib は行 95% / 分岐 95% / 関数 100%、フックは行 90% / 分岐 85%。閾値未満は CI が落ちる。除外コメント（/* node:coverage ignore */）は使わないnode --test --experimental-test-coverage --test-coverage-lines=... ＋ 構造テスト（除外コメントの grep）
TEST-9ミューテーション：hooks/lib/ のスコア ≥ 80%（夜間）。下回ったら Issue を自動で開く。lib を変更する PR は、生き残った変異が増えていないことを Brief に書くStryker（夜間）＋ reviewer
TEST-10契約 → テスト → 実装：バグ修正は再現テストが先に落ちるコミットを含む。新機能は lib の型（JSDoc typedef）とフックの入出力スキーマを先にコミットし、tsc が通ってからテストを書くreviewer（git log のコミット順）＋ このリポジトリ自身の Vouch フック
TEST-111テスト1主張。テスト名は英語の文で「対象 ＋ 条件 → 期待」（例 appendEvent rejects a type missing from the registry）。日本語はコメントにreviewer
TEST-12時間：1テスト ≤ 5 s（--test-timeout=5000）、CI の全体 ≤ 90 s（夜間を除く）。再試行（--test-retries や CI の retry）は禁止。不安定なテストは同じ PR で直すか削除するCI 設定 ＋ 構造テスト（CI 設定の grep）
TEST-13テストは core/skills/ を実行時に読まない（content テストを除く）。必要な内容は fixture にコピーする。テストが他のテストの出力に依存しないdependency-cruiser ＋ 構造テスト

フック：core/hooks/vouch-check-citation.mjs

// @ts-check
import { run } from "./lib/io.mjs";
import { readArtifact, projectRoot } from "./lib/fs.mjs";
import { checkCitations } from "./lib/citation.mjs";

/**
 * PostToolUse(Write|Edit): 成果物の「## 参照元」の参照先が存在し、最新世代かを検査する。
 * 判断はしない。検査結果を返し、空の参照元だけを遮る（HOOK-5）。
 * @type {import("./lib/io.mjs").HookMain}
 */
export async function main(input, ctx) {
  const path = input.tool_input?.file_path;
  if (!path || !/vouch\/intents\/[^/]+\/(intent|design|review)\.md$/.test(path)) {
    return { decision: "allow" };                     // 対象外は何もしない（HOOK-2）
  }
  const artifact = await readArtifact(projectRoot(input), path);  // root 配下に解決（HOOK-14）
  const result = checkCitations(artifact, ctx.generation);        // 純粋関数（lib）
  return {
    decision: result.empty ? "deny" : "allow",
    reason: result.empty ? "REF-EMPTY: ## 参照元 が空です。根拠にした知識を書いてください" : undefined,
    events: [{ type: "hook.check", check: "citation", result: result.empty ? "fail" : "pass",
               missing: result.missing.length, stale: result.stale.length }],   // 台帳にある型（HOOK-10）
  };
}

run(main);   // stdin を検証し、例外を捕捉し、events を appendEvent し、exit 0/2 を決める唯一の入口

契約テスト：tests/hooks/vouch-check-citation.test.mjs

import { test } from "node:test";
import assert from "node:assert/strict";
import { sandbox, runHook, event } from "../helpers/index.mjs";

test("check-citation denies an artifact whose ## 参照元 is empty", async (t) => {
  t.plan(3);                                                          // TEST-2
  const sb = await sandbox({ intent: "minimal", clock: "2026-09-27T00:00:00Z" });   // TEST-4/5
  await sb.write("vouch/intents/260927-x/intent.md", sb.template("intent", { sources: [] }));

  const r = await runHook("vouch-check-citation.mjs", event("claude", "PostToolUse", {
    tool_name: "Write", tool_input: { file_path: sb.path("vouch/intents/260927-x/intent.md") },
  }), { cwd: sb.root });                                               // TEST-3: 子プロセス

  assert.equal(r.exitCode, 2);                                         // HOOK-3
  assert.match(r.stderr, /REF-EMPTY/);
  assert.deepEqual(sb.audit().map((e) => [e.type, e.check, e.result]),
    [["hook.check", "citation", "fail"]]);                             // HOOK-6/10
});

test("check-citation is idempotent for the same input", async (t) => {
  t.plan(1);
  const sb = await sandbox({ intent: "minimal" });
  const ev = event("claude", "PostToolUse", { tool_name: "Write",
    tool_input: { file_path: sb.path("vouch/intents/260927-x/review.md") } });
  await runHook("vouch-check-citation.mjs", ev, { cwd: sb.root });
  await runHook("vouch-check-citation.mjs", ev, { cwd: sb.root });
  assert.equal(sb.audit().length, 1);                                  // HOOK-9
});

test("check-citation ignores malformed stdin and exits 0", async (t) => {
  t.plan(2);
  const sb = await sandbox();
  for (const bad of ["", "not json", "{}", '{"tool_input":{"file_path":"../../etc/passwd"}}']) {
    const r = await runHook("vouch-check-citation.mjs", bad, { cwd: sb.root, raw: true });
    if (r.exitCode !== 0) assert.fail(`exit ${r.exitCode} for ${JSON.stringify(bad)}`);
  }
  assert.equal(sb.audit().length, 0);                                  // HOOK-2/14
  assert.ok(true);
});
