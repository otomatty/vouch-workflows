# 配布先 doctor の契約

## 対象と境界

実装ルール DIST-5 の `node .claude/hooks/vouch-doctor.mjs` と、同じ内容の Codex 配布を実装します。これは stdin のイベントを受けるフックではなく、利用者が明示的に実行する診断コマンドです。ハーネスへのイベント登録は行いません。コマンドとイベントフックの分類は runtime レジストリで管理し、DIST-3 の双方向検査はイベントフックを対象にします。元仕様の記述は変更しません。

doctor は配布された自身の位置からプロジェクトと配布ディレクトリを特定します。cwd、VOUCH_PROJECT_ROOT、VOUCH_HARNESS、stdin を診断先の推測に使いません。サブディレクトリからの起動も同じ配布を診断します。core に `.claude/` や `.codex/` を書かず、ハーネス固有の登録ファイル名は配布データから読みます。

実行に必要なのは Node.js 22.19.0 以上と Git です。npm、開発依存、Git 初期化、Intent の作成は要求しません。Git は shell を介さず `git --version` だけを実行し、1.5秒で打ち切ります。ネットワーク、設定修復、信頼設定の変更、監査ログの生成は行いません。

## 入出力と検査

stdout は doctor-report.schema.json に従う1行の JSON です。`v:1`、全検査成功を表す `ok`、`checks:[{id,ok,detail}]` を返します。成功は終了0、不足や検査不能は終了2です。記録系フックの fail-open とは別の契約です。診断処理の例外も io の入口で JSON の失敗結果へ変換します。静的 import 自体が壊れて起動できない場合は Node が非0で終了し、JSON 出力は保証しません。

検査するのは次の範囲です。

- Node の最小版と Git の実行可否。
- runtime レジストリが列挙する配布ファイルの存在、通常ファイルであること、UTF-8。既存の fs 境界を使い、リンクや配布外参照を拒否する。
- installation.json のハーネス名と登録ファイルの宣言。
- 現在の登録 JSON に、配布した登録テンプレートの必要項目が残っていること。無関係な設定・別の hook の追加は許容する。args 配列は順序・長さを含めて一致させる。
- 宣言された追加設定ファイルの存在。Codex の TOML は存在・読み取りの検査までとし、意味の検証は未実装として表示する。

登録テンプレートは既存の settings.json / hooks.json を manifest で別の場所にもコピーします。package.mjs で設定内容を組み立てたり、ハーネス別の内容分岐を増やしたりしません。runtime.json のファイル一覧は core の実在ファイルと content テストで照合します。

この診断は、配布のソースとのバイト一致、ハーネスが設定を信頼したこと、イベントが実際に発火したこと、ワークフロー全体の完成を証明しません。これらは package:check、実機検証、後続のシナリオ検査で別に扱います。

## 実装順と検証

契約と JSDoc → テスト → 実装の順でコミットします。単体テストはファイルと Git の結果を注入し、子プロセスを起動しません。配布先テストは空の Git 未初期化プロジェクトに生成物だけをコピーし、Node の子プロセスで実際の doctor を実行します。正常例と、欠損・登録改変・リンクの負例で stdout / stderr / 終了コードと無書き込みを観測します。手製の診断データをハーネスの実機イベント fixture と扱いません。

記録フックの性能予算とケース5秒、check 全体90秒は変更しません。doctor の導入で既知の性能失敗を合格に置き換えません。オーケストレータ Skill の `/vouch doctor` と Node 未導入時の説明は後続です。
