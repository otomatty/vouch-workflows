# ランタイムの分割と読みやすさ

2026-09-30、Issue #7 の実装中に所有者から「コーディング規則を見直す」指示を受け、以下を現行の規則とする。実装ルール HOOK-12 の lib 合計上限と P-7 の増額手続きについて、この文書が優先する。元仕様は当時の記録として保持する。

## サイズと責務

フック入口はハーネス入力の受け渡しに集中する。知識の検査は共通形式、鮮度、引用、判断依頼、検査の実行・監査を別モジュールに置く。検査間で文書形式の解釈とファイル境界を重複実装しない。公開関数名から対象と検査の責務を説明できる分割にする。

1ファイルの上限（lib 300行・フック150行）は維持し、lib 全体の固定行数上限は廃止する。合計はテストで計測・表示し、機能の増加と変更量をレビューするために用いる。ファイル数やコメントを減らすこと、無関係な処理を1ファイルへ集めること、行数上限を通すために改行を詰めることを目標にしない。既存モジュールの広範な移動は今回行わず、今後の変更で責務の混在が発生した時に分割する。

## 依存とテスト

依存は入口 → 実行・監査の組み立て → 機能別検査 → 共通形式・ファイル境界の方向とする。循環依存、未解決 import、ネットワーク、実行時パッケージ、fs 境界外の直接 I/O は既存の dependency-cruiser / Biome 検査で拒否する。知識の形式・鮮度・引用・判断依頼の各モジュールが、上位の実行・監査モジュールやフックを import しないことも自動検査する。

機械的な存在・世代・形式の検査と、モデルや人による意味の判断を混ぜない。Git とディスクの入口は注入可能にし、unit はプロセスを起動せず境界条件を検証する。製品入口は採取済み入力に基づいた子プロセステストで検証する。型検査、lib 行95%・分岐95%・関数100%、hooks 行90%・分岐85%、時間予算、既存 fixture / golden の保護は維持する。

## 検証との対応

`budgets.json` / 同 schema はファイル単位の上限を保持する。`tests/content/budgets.test.mjs` が各ファイルを検査し、lib 合計は診断として表示する。`.dependency-cruiser.cjs` が実行時依存と分割した知識検査の依存方向を検査する。コーディング規則を見直したことと、既存コード全体の責務の混在を解消したことは区別する。
