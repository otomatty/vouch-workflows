# Status と共通文書の契約

## 対象と正典

決定記録 §4・§5・§11・§15 と優先する §18 に従い、Vouch Skill に読み取り専用の status を追加します。状態機械、状態キャッシュ、状態を推測する実行時関数、ステージの自動遷移は作りません。引数なしの再開、ask / report / migrate、ステージ Skill、statusline と SessionStart の再開要約は別の未実装項目です。

project-documents.json にステージと成果物の対応、判断記録・監査ファイル名、rules の節 ID、共通ルールの R-PROJECT タグを置きます。既存 workflow.json がステージ順・言語・確認点の既定の正典です。rules-frontmatter.schema.json は workflow の言語と確認点の列挙を参照し、language / checkpoints を検証します。成果物の status 値の列挙や遷移表は今回定義しません。実行時関数とその JSDoc API の追加はありません。

## Status の観測と完了条件

status は同じ配布先の doctor を先に実行し、Node が利用できることを確認します。doctor が失敗・未起動・結果不正なら、その診断と状態表示を実施していないことを返します。Node 不在時に縮退しません。

利用者が指定した Intent を対象にし、指定がなければ vouch/intents の候補を一覧にします。候補が一つなら選べますが、複数なら更新時刻で勝手に決めず、候補を示して選択を求めます。対象が存在しなければ未作成と伝え、フォルダを作りません。リンクや配布外の参照を辿って別プロジェクトへ広げません。

対象の成果物の frontmatter status と、decisions.md、監査ログを根拠として読みます。表示するのは対象 Intent、各成果物の宣言値、根拠付きの現在地、確認点、未回答の判断依頼、証拠の不足・矛盾です。

- ファイルの存在や最新イベントだけで完了を決めない。未知の status は原文と未解釈である旨を示す。Design の省略は承認済み計画などに根拠がある時だけ示し、欠損を省略とみなさない。
- approved の宣言、承認イベントの存在、人の承認の真正性を区別する。現在は真正性を検証するフックが未実装であり、JSON の actor:human を証明としない。
- 確認点は workflow の topic / unit / section と high_risk_adds に合わせて整理する。確認記録が不足していれば未確認とし、確認済みの値を捏造しない。
- question.asked と回答・既定適用の parent を対応付ける。同じ Q 番号の再質問や別 Intent を混ぜない。既定案で進行済みでも人の回答済み・承認済みにはしない。未知の親や矛盾は不確実として返す。
- ログ末尾を入口に必要な範囲まで遡る。途中までしか読めなければ観測範囲を明記し、「未回答なし」と断定しない。欠損・不正 JSONL・重複や矛盾する ID があれば部分結果として示し、修復や再採番をしない。

各主張にプロジェクト相対パス・見出しまたは行・イベント ID を添えます。成果物と監査の食い違いは隠さず併記します。status の終了は観測結果の報告であり、編集、DoD 実行、承認、回答、既定案の適用、監査追記はしません。利用者から次の作業を指示されたら、その作業として別に扱います。

## 共通文書

core/AGENTS.md は両配布のルートにコピーし、Claude は harness/claude/CLAUDE.md の1行 @AGENTS.md から参照します。共通原則、ステージ、証拠・承認・監査・コミット順・禁止事項を記載し、60行予算を守ります。製品利用プロジェクト向けの配布物であり、このリポジトリ直下の運用設定へ自動導入しません。

ja / en の rules.md テンプレートは同じ節 ID と順序を持ちます。既定の checkpoints は topic、language は選んだテンプレートの言語です。節は configuration / dod / restrictions / dependencies / checkpoints / corrections です。DoD の依存監査は全リスク階層で必要ですが、具体的なコマンドはプロジェクトで決めるまで未設定として扱い、空欄を合格にしません。制約は根拠と適用範囲を記入し、架空の禁止事項を増やしません。

テンプレートは各ハーネスの templates/ja と templates/en に同梱します。vouch/rules.md を自動作成・上書きせず、採用時に利用者が言語と内容を選びます。常時読み込み予算は AGENTS.md・オーケストレータ・選んだ言語の rules テンプレートの合計で検査します。ルール文書に必要な図は diagrams.json の成果物に該当しないため追加しません。

## 強制手段とテスト

共通の意味上の制約は R-PROJECT-1〜7 として enforcement-map に追加します。既存の実装ルール57件は保持し、追加した規則の正典を project-documents.json と照合します。これらの規則は当面モデル・人のレビューで扱い、遮断フックの完成とは記録しません。各規則の根拠は決定記録の節へ直接リンクします。

契約・スキーマ → 型検査 → 失敗するテスト → 実装の順でコミットします。content で実文書の frontmatter、日英の節順序、正典との対応、強制語タグ、行数・トークン、ハーネス非依存を検査します。配布の原本との比較は content で行い、packaging / scenario は生成物の文書を読みます。テンプレートは新しい golden と全文比較し、追加時に UPDATE_GOLDEN=1 を明示します。元の golden は変更しません。

モデルが状態を判断した結果は通常のテストで代用しません。tests/eval に手製と分かる入力セット・評価観点を置き、構造の検査とモデルの実行評価を分けます。後者は今回未実施として残します。実機イベント fixture、既存資料、フック本体、既知の時間予算には変更を加えません。
