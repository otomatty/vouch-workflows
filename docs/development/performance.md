# Windows の性能改善

## 契約

決定記録 §18 と実装ルール HOOK-13 / TEST-4 / TEST-8 / TEST-12 に従い、p95 200ms未満、20回の計測、CPU数並列、各ケース5秒、check全体90秒を維持します。起動時間の差し引き、ウォームアップの除外、再試行による合格扱いはしません。元仕様・既存fixture・goldenは変更しません。

2026-09-28、変更前 d35722a の単独交互計測では、Node 24.13.0 の p95 は空プロセス132.5ms、ESM空プロセス121.8ms、固定時計だけ145.8ms、記録なし163.1ms、通常記録207.2ms、固定時計付き記録209.7msでした。この診断は契約テストの合否の代わりにしません。

配布物128ファイルの一致検査では lstat 4,424回、exists 450回、readFile 256回、検査本体449.7msを観測しました。記録用FileStoreの20回の読取・追記は299.2ms、lstat 640回でした。これらはプロセス起動を含まない原因調査です。

## 配布検査の変更

package.mjs は同期の事前検査で、同じパスの種別とリンク確認結果を再利用します。1つのパスは同じ工程で一度だけ lstat します。不在もその工程内だけの観測値です。ディレクトリを列挙する際は、同じ検査結果でファイル・ディレクトリ・未対応の種別を判定し、exists / lstat を繰り返しません。

ソース読取と既存出力の列挙が終わったら観測値を破棄します。全出力先を変更する前に、ファイルと祖先を再検査します。列挙後に祖先がリンクへ差し替わった場合も、この再検査で拒否します。既存リンク・junction・複数リンクのファイルを拒否し、検査失敗時に書かず、--check が一切修復しない契約を維持します。観測値をプロセス外に保存したり、FileStore の監査処理へ流用したりしません。

これは同じOS権限を持つ別プロセスによる、最後の検査と書き込みの間の差し替えを完全に防ぐ機構ではありません。既存の境界をそのような保証として拡大しません。

## テストのスキーマ検査

テスト用 validator(name) は、読取専用の正典スキーマをプロセス内で一度登録し、名前ごとのコンパイル結果を再利用します。戻り値の errors は Ajv の通常の契約どおり直前の同期呼び出しの結果です。合否を保存するキャッシュにはせず、各入力を毎回検証します。未知名は従来どおり拒否します。テスト実行中に正典スキーマを書き換える使用法は対象外です。

runHook は初回呼び出し時に fixture スキーマを準備します。sandbox / fakeClock / memoryFiles だけを利用するファイルではコンパイルしません。fixtureの由来と版・入力・未知フィールドなどの検査内容、ハーネス別の適格性、計測の開始点は変えません。

契約、先行テスト、実装の順でコミットします。副作用のない観測用preloadで実際の配布処理のlstat回数を数え、工程間のリンク差し替えを隔離した一時ディレクトリで再現します。変更前に落ちる回数検査と、既存のリンク拒否・全バイト比較・配布先シナリオを合わせて検証します。
