# Codex レビュー入口の実機検証

## 契約

このコマンドは開発時の手動実機検証用です。配布物・通常のcheck・モデル評価には含めません。Codex CLIの絶対パスを明示して起動し、reports配下に毎回新しいプロジェクトとCODEX_HOMEを作ります。ユーザーの既存設定や信頼状態は変更しません。

環境は実行に必要なOS変数だけを引き継ぎます。WindowsではPathとPATHEXTを保持し、大小文字違いを正規化します。PATHが空、またはPATHEXTに.EXEがない環境は実機起動前に拒否します。認証情報、プロキシ、NODE_OPTIONS、既存のCODEX_HOMEやVOUCH設定は継承しません。検証専用のroot・Intent・homeを設定し、親側のVOUCH_HARNESSは意図的にclaudeにします。配布登録がcodexへ設定し直すことを観測します。

PowerShellまたはshから名前でnodeを起動する事前検査を行います。終了コードだけでなく実際のNodeバージョン出力も確認します。PowerShellでnodeが見つからない場合に終了コード0になる経路を成功扱いしません。

変更していないdist/codexをコピーし、hooks/listが返すそのプロジェクトのSessionStartとUserPromptSubmitの登録だけを、正確な定義ハッシュで隔離設定に信頼登録します。追加フックや登録コマンドの相違があれば停止します。信頼チェックのバイパスオプションは使いません。

プロバイダーはループバックの試験サーバーで、要求を数え、常に400を返します。プラグインと起動時の更新確認は無効にします。モデル応答を生成しません。生成済み登録のまま対話CLIへvouch reviewを渡し、ゲートが記録された場合だけ、そのIDを指定するvouch approveを別の対話CLIへ渡します。CLIにはworkspace-writeを指定します。各起動は観測後に終了させ、40秒以内に観測できない場合も終了させます。終了をフック自身の成功コードとは解釈しません。

成功条件は、期待した2操作の観測、各セッションのsession.started、スキーマに適合するcodexの監査レコード、ゲートと承認の親子・版の一致、プロバイダー要求0件、下書きと配布ファイルの不変性です。失敗時も採取できた結果をsummary.jsonに保存し、終了1を返します。生のCLI画面出力は対話端末に表示します。

保存物は実機で製品登録が動いた証拠です。stdinを採取したfixture、手製イベント、golden、人による承認、モデル評価とは区別します。actor:humanという監査フィールド自体を同意の証明にはしません。真正性保証・状態更新の許可・Build許可は引き続き対象外です。

## 確認した原因

2026-09-28、前回の検証スクリプトの環境変数の絞り込みにPATHEXTが含まれていませんでした。その環境ではWindows PowerShell / PowerShell 7のどちらもnodeを名前で起動できず、終了0とCommandNotFoundを返しました。PATHEXTを保持すると同じコマンドがNode 24.13.0を起動して終了2を返しました。

製品配布を変えずPATHEXTだけを検証環境へ戻したところ、Codex CLI 0.153.4からsession.started 2件、gate.opened 1件、intent.approved 1件を観測しました。プロバイダー要求は0件、下書きは不変でした。この原因特定用の試行はread-only指定です。正式な手動検証コマンドでは配布設定と同じworkspace-writeを検証します。

[以前の失敗記録](performance.md)は残します。登録が壊れていたとする証拠ではなく、今回判明した検証環境の不備として補足します。

## 実行方法と検証記録

配布物を生成してから、対話端末でCLIの絶対パスを指定します。

```powershell
node scripts/package.mjs
node scripts/check-codex-review.mjs C:/Users/saedg/.bun/bin/codex.exe
```

このPCではNode 24.13.0とCodex CLI 0.153.4で実行しました。workspace-writeの実機検証は成功し、session.started 2件・gate.opened 1件・intent.approved 1件を記録しました。ゲートと承認の文書ハッシュ・親子関係・待ち時間・入力ハッシュの検査も成功し、プロバイダーへの要求は0件でした。Intent下書きとコピーした配布ファイルは不変です。

記録時刻は2026-09-27 16:04 UTC、日本時間では2026-09-28 01:04です。実行結果はローカルの `reports/codex-review-5mDtPJ/summary.json` に保存しました。CLI終了は検証側による終了で、終了コード欄はnullです。フックの記録とCLIの起動・終了を区別しています。

初回の検証コマンドでは親のTERM=dumbを引き継いでCLIが起動を拒否しました。これは失敗として保存しています。WindowsではTERMを引き継がずネイティブ端末を使うよう変更してから、上記の実行を行いました。PATH / PATHEXTや認証情報の扱いと合わせて回帰テストで固定します。

原因特定時のread-only観測は `tests/fixtures/native/codex-review-0.153.4.json` に保存しました。これは製品の監査出力と試行結果であり、ハーネスstdinのfixtureではありません。元のpayload・golden・資料は変更していません。新規検証関数が未実装の状態でテストの失敗を確認してから実装しました。

## 残る検証

今回確認したのはWindowsの対話CLIと明示した2操作です。LinuxでのCodex CLI、非対話経路、他のCLI版、異常系全般を対応済みとは扱いません。その後、Linux の Codex 0.153.4 の exec・対話 CLI で、配布登録の終了0/2の伝播と異常系の一部を確認しました（[版付き fixture と伝播の検証](harness-fixtures.md)）。Windows の非対話経路と他の版は引き続き未確認です。真正性保証・監査への書き込み保護・状態更新の阻止は未実装です。Windowsの記録性能3件も従来どおり未達で、実機確認の成功によって時間予算を合格にしません。

登録と終了2の意味は[Codexのフック文書](https://learn.chatgpt.com/docs/hooks)を参照しました。実際に記録されプロバイダーへ進まなかったことは、上記の実機観測を根拠にしています。
